# a2llm

A GPT-style transformer written from scratch, small enough to run on a microcontroller.

**34,432 parameters. 33.6 KB of int8 weights. 257 lines of dependency-free C. Fits an ESP32.**

No PyTorch at inference, no runtime, no external libraries. The training code is PyTorch; the engine that ships is C.

---

## Sizes

| Model | Params | int8 weights | Target |
|---|---:|---:|---|
| `nano` | 34,432 | 33.6 KB | ESP32, ESP32-S3, ESP32-C3 |
| `micro` | 120,064 | 117 KB | any laptop |
| `mini` | 1,056,096 | 1.0 MB | normal PC, default |
| `small` | 2,763,264 | 2.6 MB | better PC |
| `base` | 4,864,000 | 4.6 MB | VPS, Colab T4 |
| `large` | 14,479,104 | 13.8 MB | GPU |

One architecture, six widths. Configs live in [`configs/`](configs).

## Try the engine in 3 commands

No ESP32 needed. The host harness compiles the same `a2lm.c` that runs on the chip:

```sh
cd esp32/host_test
gcc -O2 -I../main ../main/a2lm.c main.c -lm -o host_a2lm
./host_a2lm logits "ROMEO:"
```

`logits` prints the full 256-value next-token distribution. `generate` streams bytes:

```sh
./host_a2lm generate "ROMEO:" 0.9
```

Weights are compiled into the binary through `esp32/main/weights_data.h` (188 KB of source). Nothing is loaded at runtime.

## How it works

```
bytes ──► token embedding (256 × 32) + position embedding (32 × 32)
      ──► 2 × [ LayerNorm → causal self-attention (2 heads) → residual
                 LayerNorm → FFN 128 → GELU(tanh) → residual ]
      ──► LayerNorm → tied LM head (32 × 256) ──► logits
```

| Property | Value |
|---|---|
| Tokenizer | byte (vocab 256, no tokenizer file) |
| Context | 32 tokens |
| Layers | 2 |
| Heads | 2 |
| Width | 32 |
| FFN | 128 |
| Weights | int8 per-row scale |
| Activations | float32 |
| Memory | static allocation only |
| Randomness | xorshift32, seeded, reproducible |

The C engine mirrors the PyTorch reference exactly: pre-norm residual blocks, LayerNorm with eps `1e-5`, GELU tanh approximation, tied embeddings. The `logits` mode exists so the two implementations can be diffed value by value.

### Why byte tokens

A 256-entry vocabulary needs no tokenizer artifact, no merges file, and no preprocessing on device. The model trades sequence length for zero dependencies. At 32 tokens of context and 34 K parameters that is the right trade.

## ESP32

```sh
python scripts/export_esp32.py checkpoints/nano/best.pt   # writes esp32/main/weights.h
cd esp32
idf.py set-target esp32s3        # or esp32 / esp32c3
idf.py build flash monitor
```

UART at 115200 baud, `A2LM>` prompt. The firmware prints parameter count, int8 weight bytes, and free heap at boot, then streams generated bytes.

## Training

PyTorch, one file per preset, CPU or Colab T4:

```sh
pip install -r requirements.txt
python scripts/train.py --preset nano
python scripts/generate.py checkpoints/nano/best.pt --prompt "ROMEO:"
```

Colab notebooks, free T4:

| Notebook | Preset | Time |
|---|---|---|
| [colab_nano.ipynb](colab_nano.ipynb) | nano | ~18 min |
| [colab_micro.ipynb](colab_micro.ipynb) | micro | ~40 min |
| [colab_mini.ipynb](colab_mini.ipynb) | mini | ~30 min |
| [colab_small.ipynb](colab_small.ipynb) | small | ~1.25 h |

Pretrained checkpoints: [releases](https://github.com/ayushrajdev-dev/a2llm/releases).

```sh
python scripts/download_model.py          # list
python scripts/download_model.py nano     # ESP32 checkpoint
```

## Tests

```sh
python -m pytest tests/ -q      # 45 tests: attention, model, tokenizer, dataset, checkpoint, generation, overfit
```

`tests/test_overfit.py` verifies that a tiny model can memorize a fixed batch, which catches broken gradients before any long run.

---

## Checkpoint status

Be aware before you benchmark against a real LLM:

- `nano` (34 K) is a smoke-test checkpoint trained for 3,000 steps on TinyShakespeare. It proves the training loop and the C port work. It does not produce fluent text. Retrain with `colab_nano.ipynb` before judging quality.
- `micro`, `mini`, `small` have trained checkpoints in releases; quality scales with size and steps.
- `base` and `large` have configs but no trained weights.

The engine, the export path, and the parity harness are the finished parts. Model quality is a function of how long you train.
